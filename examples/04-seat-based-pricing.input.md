# 按席位收费正在失速：软件定价的下一次转向

过去二十年，绝大多数 SaaS 公司采用同一种定价方式：按使用者数量收费。每个员工每月固定多少钱，坐席数就是收入。这套模式之所以流行，是因为它和采购流程天然对齐——买方的人事名单就是账单，销售也很容易解释。

但它有一个结构性缺陷：它把厂商的收入和客户的人员规模绑定，而不是和客户从产品中获得的价值绑定。当一个工具帮客户自动化掉大量重复劳动时，客户并不需要给更多人开账号。于是产品越好，账单反而越小。这不是个别公司的道德问题，而是计价单位的错配。

转向按用量收费，正是为了解决这个错配。用量可以是 API 调用次数、处理的文档数量、消耗的计算资源，或者完成的任务条数。计价单位一旦贴合客户实际消费的东西，产品效率和收入增长就不再互相抵消。

不过按用量收费不是免费的午餐。它把收入波动从客户身上转移到了厂商身上：客户这个月的处理量下降三成，厂商的收入也同步下降三成，而成本结构却未必能跟着下降。按席位收费至少提供了可预测性，财务部门喜欢这一点，因为预算编制容易。

对厂商来说更棘手的问题是收入可预测性下降。按席位收费时，续约金额在合同签署那一刻就基本确定了；按用量收费时，同一批客户明年的收入取决于他们用得多不多，而厂商无法控制这个变量。这也是为什么多数转向用量计价的公司在过渡期的做法是混合制：一个较低的席位费保底，加上用量费用。

真正决定成败的往往不是计价单位本身，而是"用量"这个词是否可被客户理解和预测。如果客户拿到账单才发现自己超了额度，这个模式就会引发抵触；如果客户能在使用前看到预估并控制预算，接受度就会高得多。

对使用软件的企业来说，这轮变化的实际含义是：采购时要问清楚计价单位是什么、用量如何计量、超出套餐如何计费，而不能再只比较每席位单价。一个看起来更便宜的席位价，在用量增长之后可能远贵于按量计价的产品。

我个人的判断是，未来的主流不会是纯粹的按量计价，而是分层订阅加用量附加费的组合：基础能力打包成固定费用以满足预算需求，弹性部分按实际消费计费以对齐价值。
